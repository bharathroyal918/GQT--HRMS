## 14. Cross-Cutting Requirements

> These requirements span all phases and modules. They are enforced as platform-wide constraints, not specific to any single workflow step.

| REQ-ID | Category | Description | Business Purpose | Proposed Module | Key Business Rules | Status |
|---|---|---|---|---|---|---|
| REQ-CROSS-001 | Authentication | All platform access requires valid JWT authentication via HttpOnly cookie | Prevent unauthorised access to any platform data | `accounts` (MOD-001) | 1. JWTs expire; refresh tokens are managed server-side. 2. Concurrent session management is enforced. 3. Failed authentication attempts are rate-limited and logged. | CONFIRMED |
| REQ-CROSS-002 | Authorisation | Role-based access control (RBAC) is enforced on every API endpoint | Ensure actors can only access data and perform actions permitted for their role | `accounts` (MOD-001) | 1. Every endpoint declares its required permission. 2. Permission checks are server-side — no client-only access control. 3. Privilege escalation attempts are logged as security events. | CONFIRMED |
| REQ-CROSS-003 | Audit Trail | Every create, update, approve, and delete action is logged with actor identity, action type, entity ID, and timestamp | Maintain complete traceability for compliance, dispute resolution, and process improvement | `core` (MOD-013) | 1. Audit logs are append-only. 2. No actor (including Admin) can delete audit entries. 3. Audit log access is restricted to Admin role. | CONFIRMED |
| REQ-CROSS-004 | PII Protection | Student PII must be stored encrypted at rest and excluded from logs, error messages, and API responses to unauthorised roles | Comply with data protection obligations and protect student privacy | `accounts`, `students`, `placements` | 1. PII fields: name, email, phone, CGPA, programme. 2. Encryption at rest required. 3. PII is never included in error stack traces. | CONFIRMED |
| REQ-CROSS-005 | Notification Architecture | All notifications (email, in-app) are dispatched via a centralised notification service | Ensure consistent delivery, logging, and preference management for all communications | `core` (MOD-013) | 1. | REQ-CROSS-006 | File Security | All uploaded files (resumes, creatives, offer letters) are validated for type, size, and malware before storage | Prevent malicious file uploads and protect system integrity | `core` (MOD-013) | 1. | REQ-CROSS-007 | Soft Delete | No business record is hard-deleted from the system | Maintain historical completeness and enable audit and reconciliation | All modules | 1.
